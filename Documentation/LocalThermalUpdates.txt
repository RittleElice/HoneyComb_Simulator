열교환 연결·계수 부분 갱신 (2026-11-01)

수식과 매분 Burst Gather 계산은 유지한다. 에너지 저장, 60초 간격, 0.1 유효 교환 비율 및 외기5W/m²/K도 변경하지 않는다.

변경 감지
- EquipmentThermalState에 격자별 실제 열용량·X/Z 전도율·Y 전도율 변경 버전을 기록한다.
- MarkDirty 호출만 있었고 수치가 같다면 연결 계수를 다시 계산하지 않는다.
- 여러 번 Refresh한 뒤 계수를 소비해도 각 격자의 마지막 변경 버전을 통해 누락하지 않는다.
- 소방/밀랍 캐시를 준비하는 기존 장비 내부 과정 자체를 개별 소방 이벤트 기반으로 바꾼 것은 아니다.

계수 갱신
1. 변경된 격자에 접하는 기본 열교환 계수와 해당 격자의 외기 계수를 갱신한다.
2. 변경된 연결의 양 끝 격자에서 원래 면 순서대로 총 기본 계수를 다시 합산한다.
3. 각 격자의 교환 비율 제한을 다시 구한다.
4. 제한 비율이 바뀐 격자에 접하는 연결까지 유효 계수를 갱신한다.
5. 영향받는 격자의 유효 계수 합과 최솟값 트리를 갱신한다.
6. 계산용 NativeArray에서 변경된 연결·외기 행만 덮어쓴다.

기본 계수 변화는 직접 이웃의 제한 비율을 바꾸고, 그 이웃의 다른 연결에도 영향을 준다.
단순히 변경된 격자의 여섯 연결만 고치는 방식이 아니다. 기본 합으로 제한을 정하므로 이 범위 이후의 재귀 전파는 없다.
합계에 차이를 더하고 빼는 누적 갱신은 사용하지 않는다. 기존과 동일한 더하기 순서를 유지해 반올림 차이를 방지한다.
최초 생성은 전체 선형 계산 경로를 사용하며, 큰 dirty 목록을 생성하지 않는다.

장비 이동
- 동일한 공간 격자 목록·독립 장비 목록·조립 접촉 관계를 유지하는 이동은 기존 격자망과 RAM 배열을 유지한다.
- 변경된 박스의 격자 소유자 매핑을 비교하고, 실제로 바뀐 격자와 주변 계수만 갱신한다.
- 소비장의 박스 안 슬롯 이동 및 박스 간 이동이 이 경로에 해당한다.
- 새로 노출된 공기는 기존 정책대로 외기 온도로 초기화한다. 장비 에너지는 장비 소유 상태를 그대로 참조한다.
- 비교용 매핑 스캔은 변경된 박스 단위로 수행한다. 모든 과정이 O(변경 격자 수)만으로 끝나는 것은 아니다.

전체 재구성 유지 범위
- 소비장을 손/소지품으로 분리하거나 다시 삽입하여 활성 격자 수가 달라지는 경우.
- 새 장비 추가·제거, 뚜껑/계상 결합·분리로 격자 또는 조립 접촉 관계가 바뀌는 경우.
- 장비 목록 순서가 달라져 기존 인덱스 배열을 그대로 유지할 수 없는 경우.
이 경우 기존 전체 빌더를 사용한다. 전체 재구성 비용을 없앤 구현은 아니다.

검증
- LocalThermalUpdateTests: 전체 원래 수식으로 다시 구한 계수 합·외기 계수·안정 시간과 비트 단위 대조.
- 한 영역 내용물 변경 시 변경 격자1개/기본 연결6개/유효 연결6개 갱신.
- 소비장 이동 시 두 위치의560개 격자와 기본2056개/유효4520개 연결 갱신(시험 구성).
- 244개 변경 전후 SHA256 지문: 240분별 전체 격자 에너지·열용량·온도 및4개 저장본 일치.
- 열교환/외기/소방/저장/날씨 회귀검사 포함.
- 버전·연결 캐시는 RAM 전용이며 저장 형식4는 그대로 유지한다.
