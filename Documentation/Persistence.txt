저장 기능 (2026-10-31)

사용 방법
- 양봉장/관찰 화면 우측 상단의 저장 버튼: 현재 월드를 수동 저장한다.
- 자동 저장: 초기 30초 간격. 저장 비용에 따라 10~120초 범위에서 조절한다.
- 메인 메뉴 이어하기: 정상 저장본 전체 복원 → 남은 시간 점프 및 오프라인 분 계산 → 플레이 가능.
- 새 게임: 기존 저장 파일이 있으면 게임 화면에서 교체 확인을 받는다. 저장 슬롯은 1개이며 정상 세대 2개를 번갈아 유지한다.
- 저장 완료/진행/실패를 화면에 표시한다. 쓰기 실패 시 이전 정상 저장본을 유지하며 재시도한다.

저장 위치 및 파일 안전성
- Application.persistentDataPath/Saves/world-a.save, world-b.save.
- 현재 Windows 설정: %USERPROFILE%/AppData/LocalLow/DefaultCompany/HoneyComb_Simulator/Saves.
- 각 파일은 버전, 세대 번호, 데이터 길이, SHA-256 검증을 포함한다.
- 새 파일을 .tmp에 작성하고 Flush(true) 후 오래된 세대만 원자적으로 교체한다. 가장 최근 정상 파일은 건드리지 않는다.
- 불완전한 .tmp는 읽지 않는다. 최신 정상 파일이 손상되면 다른 정상 세대를 읽는다. 둘 다 손상되면 실패를 알리고 파일을 보존한다.
- 파일 교체 기능이 지원되지 않거나 디스크 쓰기가 실패하면 저장 실패로 처리한다. 이전 파일을 지우는 비원자적 대체 절차는 없다.
- 체크섬은 손상 검출용이며 암호화나 치트 방지 수단이 아니다.

현재 모델의 저장 범위
- CurrentGameMinute, UTC 기준/소수 잔여/시계 역행 상한, 계산 중 남은 절대 목표 분.
- 양봉장 이름/전체 크기/해금 너비/각 슬롯, 벌통 목록 및 기존 HiveData 슬롯/좌표.
- 인벤토리 슬롯과 손의 장비, 조립체 순서, 내부/상단 장비 슬롯, 소유권 구조.
- 장비 ID/이름/종류/노후도, 단열·격리판의 사용자 정의 공간 프로필.
- 소비장 앞/뒤 및 현재 면, 소방 종류/건설률/완성 이력/내용물/봉개율/기존 표시용 충전율.
- 밀원별 당 질량과 반복 순서, 물·화분 질량, BeeId. 저장 당시 물량을 현재 용량 제한으로 잘라내지 않는다.
- 공간 격자, 열용량 집계, UI 캐시/이벤트는 원본 상태에서 재생성한다. 카메라 위치·선택 강조·손 애니메이션은 저장하지 않으며 이어하기는 양봉장에서 시작한다.
- 전역 밸런스 설정은 프로젝트 에셋을 사용한다. 세이브가 설정 에셋을 덮어쓰지 않는다.

시간 및 중단 복구
- 스냅샷은 메인 스레드의 완료된 틱 경계에서 캡처한다. 디스크 기록/검증은 분리된 바이트로 백그라운드에서 실행한다.
- 비동기 틱의 부분 변경 상태와 실패한 틱은 저장하지 않는다.
- 시간 점프는 시작 목표를 먼저 저장하고, 계산 도중 적응형 체크포인트를 기록하며 완료 시 다시 저장한다.
- 체크포인트의 목표 분은 진행 중 점프 + 대기 중 오프라인 분을 포함한다. 다시 시작하면 남은 목표에 새 UTC 경과분만 추가한다.
- 복귀 계산의 대상은 고정한다. 현재 실행에서 계산에 걸린 시간을 계속 새 오프라인으로 추가하지 않는다.
- 앱 pause/focus 상실과 정상 종료 시 가능한 경우 마지막 정상 상태를 동기 기록한다. 강제 종료는 콜백이 보장되지 않으므로 마지막 완료된 체크포인트로 돌아간다.
- 강제 종료의 정확한 발생 시각은 알 수 없다. 재실행 경과 시간은 마지막 정상 체크포인트의 UTC부터 측정하며, 이후 저장되지 않은 입력/변경은 복원되지 않는다.
- UTC 역행은 음수 경과를 0으로 처리하고 상한을 유지한다. 기기 시계의 큰 미래 변경은 실제 오프라인과 구분할 수 없다.

확장 시 지켜야 할 경계
- 현재 날씨·벌 solver는 등록되어 있지 않으며 이번 변경으로 연결하지 않았다.
- 알 수 없는 장비 Content, 지원하지 않는 데이터/버전/배치, 중복 소유권은 저장 또는 복원 실패로 처리한다.
- IGameMinuteParticipant가 등록되면 현재 저장 경로는 차단된다. 참가자의 월드/난수/통계 상태를 저장 형식에 포함하고 복원 경로를 추가한 뒤 이 검사를 확장해야 한다.
- BeeId를 보존하지만 아직 존재하지 않는 별도 벌 개체 모델이나 날씨 난수 상태를 저장한 것으로 간주하지 않는다.
- 스냅샷 캡처는 현재 규모에서 동기 실행이다. 대규모 월드에서는 메인 스레드 캡처 비용을 측정하고 입력·틱 잠금 상태의 분할 캡처가 필요하다.
- 파서 제한: 파일 128MiB, 전체 장비 노드 100,000, 중첩 64, 한 면 소방 1,000,000, 양봉장 격자 1,000,000. 제한 초과는 실패로 알리며 정상 파일을 보존한다.
- Android 실기기의 저장장치/강제 종료/시각적 배치는 별도 확인이 필요하다.

검증
- 월드 전체 바이트 단위 왕복 일치, 완성률 이력, 질량/BeeId, 슬롯 소유권, 세대 선택, 손상 복구, 임시 파일 무시, 지원하지 않는 상태 거부: 23개 검사 통과.
- 기존 시간·장비·격자·소방·열·관찰 테스트와 공통 버튼 57개 검사 통과.
- 실제 씬 자동 Play: 저장 UI, 장비 이동 후 저장, 계산 도중 체크포인트, Bootstrap 재생성과 이어하기, 남은 점프 및 UTC 복귀, 중복 소유권 방지 통과.
- 검증 파일은 HONEYCOMB_SAVE_TEST_ROOT로 분리했으며 실제 플레이 저장 경로는 수정하지 않았다.

- 별도 Unity 프로세스에서 이전 실행의 파일을 로드하여 손/노후도 및 UTC 오프라인 계산 복원 통과.
