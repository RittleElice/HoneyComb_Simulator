열교환 설정
메뉴: HoneyComb > Developer > Thermal Exchange
기존 Tools > HoneyComb > 격자 열교환 설정 메뉴도 같은 창을 연다.
분당 교환 제한: 0.1~50%. 기본10%. 모든 내부/외기 연결의 합산 상한이며, 개별 연결은 이보다 작다. 현재 명시적60초 계산의 허용 범위로 제한한다.
외기 열전달계수: W/(m² K), 유한한0이상. 기본5. 0은 외기 경계 교환을 끄며 내부 교환은 남는다.
현재 값 적용: 설정 객체에 반영. 실행 중인 게임도 다음 PrepareExchange/분 계산에서 계수·버퍼를 한 번 재생성한다. 기존 열에너지 및 현재 플레이 저장은 유지한다. 적용 순간의 준비 비용이 발생하지만 정상 분 계산에서는 반복 재생성하지 않는다.
적용하고 프로젝트 기본값 저장: 위 작업 후 설정 asset을 디스크에 저장한다. 설정은 플레이 저장이 아니라 프로젝트 공통 설정이다. 현재 값 적용만 해도 이후 Unity 프로젝트 저장 시 함께 저장될 수 있다.
현재 값 다시 읽기, 기본값 입력(10%,5), 설정 파일 선택 버튼 제공. 기본값 입력 뒤 적용해야 실제 반영된다.
Resources에서 로드한 ThermalMaterials는 설정 asset을 참조해 변화 여부를 읽는다. 직접 생성한 ThermalMaterials는 기존 고정 스냅샷 동작을 유지한다. 재질 밀도/비열/전도율 값은 여전히 로드 시 스냅샷이며 이 창의 실시간 설정 대상이 아니다.
기본10%와 외기계수5는 이번 변경에서 유지했다. 저장 스키마/플레이 저장 변경 없음. 바람 환기·대류·벌 발열은 추가하지 않았다.
검증: LiveThermalSettingsTests.Run. 10→50% 실시간 반영, 1회 재생성, 기존에너지/저장바이트 보존, 반복 재생성 없음, 50%에서120분 냉각 안정성, 외기5→0→25, 잘못된 입력 정규화 및 내용물/외기/버퍼 회귀 검사 통과.
