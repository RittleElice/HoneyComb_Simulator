# 벌 격자 위치·이동 적용 기록

적용 프로젝트: `C:\UnityProject\HoneyComb_Simulator`

## 적용 내용

- 벌 위치는 `BeeGridPosition(EquipmentId, X, Y, Z)` 네 정수만 저장한다. 면, 표면 ID, mm 좌표는 저장하지 않는다.
- 장비가 소유한 고체 격자에 부착된 것으로 취급한다. 신규 배치는 공기와 내부에 완전히 묻힌 격자를 거부한다.
- `GameWorld.BeeLocations.Set`으로 배치하고 `GetNeighbours`로 공유 이동 목록을 조회하며 `TryMove`로 연결이 유효한 한 단계 이동을 수행한다. `CountAt`은 해당 격자의 벌 수를 제공한다.
- 같은 장비의 이어지는 외곽과 안쪽 모서리를 연결한다. 소비장 중앙 앞뒤 사이의 내부 관통은 허용하지 않고 가장자리를 통한 이동은 허용한다.
- 연속된 두 슬롯이 모두 소비장일 때, 마주 보는 15개 격자 쌍을 연결한다. 중간 두 공기 격자도 확인한다. 빈 슬롯이나 격리판을 사이에 둔 직접 이동은 허용하지 않는다.
- 단상/계상/뚜껑 조립체의 맞닿은 격자는 같은 공간으로 조합한다. 분리된 장비는 별도 공간이므로 창고 안에서 서로 연결되지 않는다.
- 장비 이동 시 벌의 장비 내부 위치는 유지한다. 슬롯 및 공간 변경 이벤트로 공유 연결 정보를 무효화하고 다음 조회에서 재구성한다. 변경이 없으면 벌마다 그래프를 다시 만들지 않는다.
- `BeeSurfaceEnvironmentReader.TryReadAt`으로 격자 단위 온습도를 조회할 수 있다. 여러 인접 공기는 접촉 면적에 따라 온도와 수증기압을 평균하고 상대습도로 환산한다. 외부 노출도 반영하며 갱신 전의 열환경은 거부한다.
- 벌이 붙어 있는 장비는 소비장뿐 아니라 벽을 가진 장비도 쓰레기통에서 삭제하지 못한다.

## 저장 호환성

- 신규 저장 형식은 15이다. 벌 ID 뒤에 장비 ID, X, Y, Z만 기록한다.
- 형식 14의 소비장 ID/면/mm 위치는 현재 장비 격자의 구간에 따라 변환한다. 기존 정밀 좌표는 보존하지 않는다.
- 형식 13도 계속 읽으며 위치 목록은 비어 있다. 실제 사용자 저장 파일을 일괄 변경하지 않았다.

## 검증

- Unity 6000.5.1f1 배치 실행에서 프로젝트 컴파일 통과.
- BeeSurfaceTests: 88개 항목 통과. 전체 소비장 30칸 연결, 맞은편 15개 연결, 차단/재배치, 벽/외부 환경, 저장 변환 및 동일 바이트 복원을 검사했다.
- 상세 실행 결과: `tests.txt`, `unity-tests-2.log`.
- 기존 월드 저장 회귀 검사: 23개 항목 통과. `save-regression-2.log`, `save-tests.txt` 참조. 최초 실행에서 오래된 인벤토리 슬롯 가정이 발견되어, 테스트가 필요한 장비를 직접 생성하도록 테스트 준비 코드만 수정했다.

## 구현 범위와 남은 설계

- 이동은 검증된 한 단계 위치 변경 API이다. 개체 생성, 목표 선택, 자동 행동 스케줄러, 이동 속도/시간, 비행·낙하 반응은 추가하지 않았다. 아직 결정되지 않은 수치나 규칙을 임의로 설정하지 않았다.
- 같은 격자의 서로 다른 노출 면은 하나의 부착 위치로 합쳐진다. 벽 안팎이 모두 노출되면 대표 환경에 함께 포함되며, 면별 이동을 구분하지 않는다.
- 환경 읽기는 격자 단위 API를 제공한다. 대규모 행동 처리에서는 한 번 읽은 격자 환경을 해당 벌들이 공유해야 한다.
- 장비 변경 시 현재는 월드의 공유 이동 그래프를 재구성한다. 국소 갱신 최적화와 대규모/모바일 성능 검증은 수행하지 않았다.
- Unity 배치 코드 테스트이며 실제 화면에서의 조작 및 장치 검증은 별도이다.
