방법
원본 Assets/Scripts 전체가 검증용 복사본과 일치하는지 확인한 뒤 복사본 두 파일에만 계측 추가.
각 독립 벌통 모델의 9개 구간을 Stopwatch.GetTimestamp로 측정. 배열은 미리 할당하며 구간마다 할당/잠금 없음.
각 틱 종료 후 100개 모델의 구간 경과 시간을 합산. 합산은 전체 틱 시간 측정 밖에서 수행.
계측 비활성 병렬 -> 계측 병렬 -> 계측 직렬 -> 계측 비활성 병렬 순서로 동일 세계를 새로 만들어 실행.
구간 시간은 CPU 사용시간이 아닌 경과 시간. 병렬 합계에는 겹침과 스레드 대기가 포함되므로 전체 틱 시간과 직접 더하거나 동일시할 수 없음.
계측 비활성 대조군도 경량의 비활성 분기와 미리 할당된 계측 배열은 존재함.

병목과 제안 (미구현·속도 향상 미측정)
1. 결과 반영: 가장 큰 범주. CommitChanges의 전체 질량/에너지 순회와 State 재계산을 동일 순서의 Burst 커널로 묶는 방안, 소방별 수분 변경을 소비장 단위로 묶는 방안, PublishEquipmentEnergy의 장비별 일괄 갱신을 우선 검토. 공유 셀의 합산 순서, 유한값 검증, float 잔차의 공기 저장고 환원, Revision/저장 일관성을 유지해야 함.
2. 내부 수분 교환: 단일 구간 중 최대. 이미 Burst와 32개 묶음 처리 사용. 고정된 접촉 정보·경계 플래그·재질별 경로를 준비 단계에서 분리해 반복 분기/주소 계산을 줄이는 방안. 현재 틱 시작 상태에서 읽고 마지막에 합산하는 순서를 유지. 접촉 계수만 고정이라고 응답계수까지 고정하면 안 됨: 수증기압 기울기는 온도·수분 상태에 따라 변함.
3. 열 교환: 이미 열용량 변경 여부에 따른 계수 캐시가 있음. 외기 경계 접촉은 매번 갱신되는 경로가 있으므로 필요한 입력(열용량, 외기/풍속 관련 계수) 변화에 따라 캐시 무효화를 더 세분화하는 방안. 근사값 허용 전에 동일 수식/정확한 무효화 방식부터 실험.
4. 증발: 우선순위 낮음. 관리 코드의 Exp/Pow 루프를 Burst로 옮기고 같은 틱에서 재사용 가능한 계산값을 공유하는 방안. 물 감소에 따라 공기 부피가 변하므로 기하 관련 값도 무조건 상수 캐시하면 안 됨.
5. 벌통 간 병렬화는 이미 적용되어 약 4.5배 효과를 보임. 단순 스레드 증가는 우선순위 낮음. 메모리 대역폭/캐시 병목은 이번 계측으로 확정할 수 없으며 하드웨어 카운터 측정이 필요.

권장 순서: 결과 반영 일괄 처리 실험 -> 내부 수분 교환 경로 정리 -> 열 계수 갱신 축소 -> 증발.
