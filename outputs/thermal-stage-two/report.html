열환경 2단계 — 구현·검증 결과

2026-11-01 · 원본 C:\UnityProject\HoneyComb_Simulator · Unity 6000.5.1f1

판정: 현재 실제 격자에서 60초 명시적 열교환은 사용할 수 없습니다.
기본 구성의 비진동·최대원리 보장 시간은 0.2774196735초, 혼합 장비 시험 구성은 0.2527955660초입니다. 런타임에 60초 계산을 연결했으므로 현재 게임은 첫 시간 틱에서 진단 오류로 멈춥니다. 자동 시간 분할·열량 제한·암시적 전환·조용한 Solver 우회는 없습니다. 마지막 정상 저장은 유지되며 실패 후 저장은 차단됩니다. 정상적인 장시간 플레이를 위해 다음 단계의 계산 방식 결정이 필요합니다.

구현과 연결

  • 7종 재질 ScriptableObject와 물성값, float 열에너지, 열용량·유효 열전도율·공기 체적 SoA, Dirty 인덱스 목록을 유지했습니다. 캐시 갱신 성공 시 증가하는 CacheRevision만 추가했습니다.
  • 중앙 밀랍판 420×200×0.5mm, 39.9g 및 소방 건설도별 밀랍 질량·논리/물리 면적 매핑은 변경하지 않았습니다. 화밀·화분·벌·발열·잠열은 연결하지 않았습니다.
  • ThermalTopology가 배치된 장비의 원본 에너지 소유자를 중복 없이 연결합니다. 소비에 가려진 상자의 공기 원본은 활성 계산에서 제외하고, 분리된 장비는 자체 폐쇄 격자로 계산합니다. 인벤토리/손의 장비도 자체 격자는 계산하지만 서로 열을 교환하지 않습니다.
  • 내부 면과 단상–계상–뚜껑 접합면을 포함합니다. 면별 열저항은 R = dA/(kA·A) + dB/(kB·A), 전달 계수는 G = 1/R [W/K]입니다. dA,dB는 각각 중심에서 면까지의 반 두께입니다. 면적 mm²→m², 거리 mm→m 변환을 명시했습니다.
  • 각 면의 G를 한 번 계산하여 양쪽 인접 목록에 동일한 double 값을 저장합니다. 장비 배치 변경은 토폴로지 재생성, Dirty/물성 캐시 변경은 계수 재생성으로 처리합니다. 변경 없는 틱에서는 계수를 재사용합니다.
  • IJobParallelFor Gather는 공통 이전 온도 T = (double)E/C를 읽고 E' = E + 60·ΣG(Tj−Ti)를 double로 계산합니다. 격자별 별도 출력만 기록하여 경쟁 쓰기가 없습니다. Job 완료 후 모든 후보를 검사하고 float로 변환한 다음, 메인 스레드에서 중간 관측 없이 전체 소유자에 반영합니다.
  • 외부 경계는 단열(열유속 0)입니다. 자연 대류·환기·복사·외기 전달계수는 없습니다. 격왕판은 기존의 두께 0인 투과성 면으로, 근거 없는 접촉 열저항을 새로 넣지 않았습니다.

6방향 이웃 검증

현재 구성은 셀 크기가 달라도 경계 분할선이 일치하는 직교 격자입니다. 배치되는 모든 원본 장비 셀의 X/Y/Z 폭을 배치 격자와 대조하고, 적층 접합의 X/Y 좌표 배열을 비교합니다. 단상·계상은 Z층 수가 다르지만 접합면 XY 분할은 같고 뚜껑도 같은 XY를 사용합니다. 14×10 논리 소방 구역을 직접 이웃으로 사용하지 않습니다.

혼합 구성에서 내부·분리 장비·적층 접합 1,872면을 합친 정확한 연결 수를 검사했고 최대 차수는 6입니다. 고정 6방향은 현재 형상에서 유효합니다. 구현은 가변 인접 목록(CSR)을 사용하며, 향후 불일치 분할·부분 매핑·중복 소유자가 발견되면 전체 그래프를 거부합니다. 비정합 격자의 면적 겹침 계산은 아직 없으며 연결을 임의로 누락하지 않습니다.

안정성·실패 원자성

각 격자에서 dt ≤ Cᵢ/ΣGᵢⱼ를 요구합니다. 이 조건은 다음 온도가 이전 자기/이웃 온도의 비음수 가중 평균이 되게 하는 충분조건입니다. 정확한 고유값 한계 자체를 계산한 것은 아닙니다. 다만 대칭 전달 그래프에서 명시적 Euler의 스펙트럼 한계는 2·min(C/ΣG) 이하이므로 기본 구성의 실제 한계도 최대 약 0.55484초입니다. 따라서 60초 거부는 단지 보수적인 판정 때문이 아닙니다.

수치 결과와 성능

실제 물성·격자의 60초 틱은 Job 실행 전에 거부되므로 성공한 실제 60초 성능 수치는 없습니다. 아래 실제 격자 실험은 고정 0.01초 단일 틱 105회이며, 런타임의 60초를 쪼갠 것이 아닙니다. 초기 온도는 격자별 5~40°C 패턴입니다. 별도로 전달 면적을 작게 설정한 합성 접합망에서 60초 Job 경로도 검사했습니다.

날씨·저장·회귀 검증

  • 날씨 Ver 2.0은 신규 격자의 현재 외기온 초기화에 사용됩니다. 이번 단계에서 날씨 온도와 외부 열교환을 연결하지 않았습니다.
  • Scheduler 등록 순서는 열환경 → 날씨입니다. 열환경이 실패하면 날씨와 난수도 진행되지 않습니다. 정상 틱의 전체 완료 후에만 기존 시간 커밋/체크포인트가 실행됩니다.
  • V3 직렬화 형식은 그대로이며 float 에너지만 저장합니다. 그래프·전달 계수·온도 스냅샷·Job 출력은 파생 상태로 저장하지 않습니다. 복원 에너지는 외기온으로 덮어쓰지 않습니다. V1/V2 읽기와 미초기화 상태 처리도 유지합니다.
  • Unity 원본 컴파일 통과. 1단계 91,742검사, 2단계 104,265검사, 장비 조립·공간 격자·소방 상태·소방 질량/열용량·저장·시간 회귀 검사 통과. 날씨 전용 6,000분 진행·중간 저장/복원 후 난수 포함 결정적 연속성 검사도 통과했습니다. 후보 float 오버플로·NaN 시간 간격·Inf 입력 및 반영 원자성도 검사했습니다.
  • 원본 Bootstrap Play에서 새 게임 → 테스트 전용 실제 저장 → 비동기 불러오기 → 불안정 틱 → 저장 차단을 37개 검사로 확인했습니다. 기존 저장 파일의 바이트가 유지됩니다. 사용자 실제 저장 폴더는 사용하지 않았습니다.
  • 기존의 정상 1시간 진행 Play 기대값은 더 이상 만족하지 않습니다. 현재 물성과 격자의 60초 요구가 불가능하여 의도적으로 멈추는 동작을 검증했습니다.

다음 단계

  1. 현재 작은 공기 격자의 확산 시간 척도와 60초 요구를 양립시킬 방식을 결정해야 합니다. 시간 간격 변경, 물리적으로 근거 있는 격자/모델 축약, 다른 적분법은 별도 설계·승인 범위입니다. 물성을 임의로 낮춰 통과시키지 않았습니다.
  2. 외기 경계의 대류·복사·환기 및 격왕판 접촉/통과 열저항을 정의하고 실제 날씨와 연결합니다. 그 뒤 외부 유출입을 포함한 에너지 수지를 검사합니다.
  3. 기기에서 Profile하여 NativeArray 상시 재사용·Burst 적용의 효과와 비용을 검증합니다. 현재 매 틱 할당/복사는 명시적으로 남아 있습니다.
  4. 화밀·화분·벌의 질량/열용량, 물질 이동의 에너지 수송, 발열·잠열은 후속 단계로 유지합니다.
